The paper bounds how much a MAP adversary gains from the non-uniform mantissa distribution by enumerating every FP32 plaintext mantissa against every noise mantissa (223 × 221 encryptions). A uniform guess succeeds with probability 2−23.

How this was run, and what differs from the paper
  • Code: libhear at commit 88f114f with Intel MPI 2018 Update 2 (the paper used Cray MPICH), OpenSSL 1.0.2k (the code only calls SHA1()), and MPFR 4.1.0 built for the precision tests, as in the paper.
  • Compilers: the paper used clang 13, which our cluster lacks. Everything was built with the system GCC 4.8.5 (-std=c++11 added). The DNN runs use a GCC 9.3 build (Red Hat devtoolset-9) because its float encryption is fastest of the compilers we have; Intel icpc 18 was also tried. All builds pass the end-to-end memcmp check.
  • Benchmarks: the authors’ OSU 7.0.1 Allreduce benchmark (their integer patch) and their DNN proxies, run through their LD_PRELOAD interposition, with their environment variables and block sizes. MPI used the DAPL InfiniBand fabric, the fastest in a survey of all fabrics.
  • Scale: Piz Daint’s 36 cores per node become our 20, so “2 nodes, full” is 40 ranks here and 72 in the paper. Node scaling stops at 4 nodes (80 ranks); the paper goes to 32 nodes (1,152 ranks). The DNN proxies ran at 80 ranks instead of 256.
  • Iterations: 16 MiB runs use 300 iterations instead of 1000, since each takes about 3.4 times longer on our 40 Gb/s link; small messages use the paper’s 100,000.
  • Security: the authors’ driver hard-codes 95 workers for 96 ranks; we set it to all 80 ranks. Nothing else changed.
  • Fig 9: the ResNet-152 proxy ran with 5 warm-up and 10 timed iterations instead of 100 and 100, because the full run exceeded the 40-minute limit we set per run at 80 ranks. It reports the same per-iteration average.
  • Not in the paper, added to explain what we saw: synchronous HEAR at every scaling point; a control library (control/chunk.c) that chunks native MPI exactly like HEAR’s pipeline without encrypting; a run with Intel MPI’s progress threads; and the compiler comparison.
  • Fig 5’s driver script is a Python program; the compute nodes have no Python 3, so the same commands ran from a bash loop.
  • Jobs ran through the cluster’s PBS submission wrapper, on nodes with Hyper-Threading off and Turbo Boost off.
